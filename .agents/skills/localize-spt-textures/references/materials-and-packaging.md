# 보조맵·검증·패키징

## 보조맵 판단

`source.json`의 실제 재질 연결과 각 맵의 원본을 확인한다.

- N에 글자 요철이 없으면 원본을 유지한다. 육포의 판단을 모든 품목에 일반화하지 않는다.
- G에 원문 글자 효과가 있으면 그 효과를 제거하고 선택한 D의 한글 윤곽에 맞춰 반영한다.
- G의 알파는 보존한다. 지원되는 DXT5nm N의 G/A는 방향 채널이므로 변경할 수 있고 R/B를 보존한다.
- 공유 N/G는 변경하지 않는다. 원본 크기가 다르면 지원되는 같은 UV·2의 거듭제곱 축소 관계인지 확인한다.
- 별도 사용 모델이나 LOD에 편집본을 복사하지 않는다. G가 없는 품목은 D/N만 다룬다.

각 효과 영역에서 원문 흔적을 제거한 `neutral` RGBA와 원문 효과만 포함한 0/255 L 마스크를 준비한다.
장식선·사진·포장 주름을 글자로 오인하지 않는다. 육포에서 쓴 좌표·밝기 차이·잔상 제거 반경을
다른 품목의 고정값으로 사용하지 않는다. 효과의 강도와 방향은 해당 원본을 보고 정한다.

## 전체 D의 글자 윤곽 연결

`adopt-draft`로 채택한 D에서 한글 글자만 포함한 원본 크기의 RGBA 윤곽 이미지를 준비한다.
글자 밖 알파는 0이다. 전체 불투명 D를 글자 마스크 대신 넣지 않는다.
같은 위치의 N/G 효과에 동일한 윤곽을 쓰며, 일부 글자에만 효과가 필요하면 `selection`을 사용한다.

`generated-full` 작업의 `derive` 레시피에는 다음 두 필드가 추가된다.
해시는 `adopt-draft` 결과의 `candidate.sha256`을 사용한다.
모든 레시피 경로는 `job.json`의 폴더 기준이다.

```json
{
  "lettering": "layers/lettering.png",
  "diffuse_sha256": "선택한-D-후보의-SHA256",
  "maps": [
    {
      "map_id": "source.json의-gloss-ID",
      "neutral": "layers/gloss-neutral.png",
      "old_effect": "layers/gloss-old-effect.png",
      "channel_deltas": {"R": 12, "G": 12, "B": 12}
    }
  ]
}
```

수치 12는 형식 예시다. N의 레시피와 지원 범위는 [기존 편집 문서](../../../../docs/editing.md)를 따른다.
위치별로 다른 세기가 필요하면 효과 그룹에 맞게 글자 알파의 불투명도를 조정하고 원본과 비교한다.
하나의 밝기 수치를 모든 글자에 강제로 적용하지 않는다. 글자 마스크를 만드는 방법과 보정 수치를 기록한다.

```text
python localize.py derive <job.json> <derive.json>
python localize.py validate <job.json>
```

파생 기록은 선택한 D, 글자 윤곽, 선택 마스크, 원문 효과 제거 입력과 출력의 해시를 연결한다.
D를 다시 채택해도 N/G는 자동 덮어쓰기하지 않는다. 이전 N/G 기준이 맞지 않으면 검사가 실패하므로
새 D에 맞는 윤곽과 레시피로 다시 파생하거나, 이전 편집을 남길 새 작업 폴더를 준비한다.
N과 G를 따로 파생해도 각 맵의 기준 기록을 유지한다.

## 검사와 테스트 패키지

`generated-full`은 D의 RGB·UV 경계 픽셀 변화량을 보고하지만 비문자 RGB 동일성을 보증하지 않는다.
원본 해시·선택한 시안 기록·RGBA 크기·D 알파·공유 맵 제약은 검사한다.
N/G의 수정 마스크 밖 픽셀·UV 경계·보존 채널 검사는 그대로 적용한다.
마스크를 확대하거나 기준 해시를 수동으로 바꿔 실패를 숨기지 않는다.

```text
python localize.py package <job.json> --dotnet <사용 가능한 .NET 10 실행 파일>
```

패키지에 D 제작 방식과 보존 범위를 표시한다. 원본 압축 포맷·밉 수·비대상 번들 데이터를 보존하고
재개봉 검사를 실행한다. 오류를 없애려고 해상도·포맷을 변경하지 않는다.
자세한 패키지 구조와 게임 확인 후 배포는 [검증 문서](../../../../docs/validation.md)를 따른다.

설치 요청 시 이미 준비한 테스트 패키지를 현재 모드에 반영하되 기존 다른 품목을 보존한다.
게임 설치 위치는 실제 SPT 루트에서 확인하고, 원본 게임 번들 대신 서버 모드의 번들을 사용한다.
현재 대화의 백업·설치 범위 지시를 우선하며 이미 받은 승인을 다시 요구하지 않는다.
파일 검사만으로 실제 게임의 글자·반사·거리별 표시를 확인했다고 기록하지 않는다.
