# 품목별 작업 구조로 재구축

## 기준과 보존

2024-12-02의 `fd33a0e`는 SPT 3.10용 파일 6개를 가진 마지막 올해 이전 커밋입니다.
현재 SPT 4.1 모드와 원본 포맷·번들 처리 수정이 빠져 있어 작업 기반으로 되돌리지 않았습니다.
`4ddf197`에서 `codex/rebuild-texture-workflow` 브랜치를 만들고 필요한 구현을 이관했습니다.

기존 작업 폴더는 수정하지 않았습니다. 기존 미커밋 변경, 스킬에서 패키지로 옮기던 검사기,
텍스처와 최근 품목별 실험은 원래 작업 폴더와 별도 백업에 남습니다.
최신 미커밋 소시지·보드카 번역 제안은 새 프로필에도 복사했습니다.
이전 전체 파이프라인의 승인 기록은 새 작업의 시각·게임 승인으로 자동 승계하지 않습니다.

## 남긴 기능

- 실제 Material/PPtr와 Renderer/Mesh 연결 조사, 외부 번들 및 공유 보조맵 발견.
- UV 경계와 coverage 추출, Normal 방향 벡터·Gloss 선형 효과 계산.
- 원본 포맷·밉·알파와 UnityFS 구조 보존, 재개봉과 압축 왕복 검사.
- SPT 4.1 서버 모드 메타데이터.
- 기능과 함께 유지한 자산 독립 테스트.

## 정리한 기능

- `tools/auto.py`, `tools/maps.py`, 중단된 배포 경로와 과거 조판 구현 제거.
- 검토 스킬과 다단계 OCR/타이포그래피 승인 게이트, 전체 품목 완료 의존성 제거.
- HiResInspect·4096/BC7 강제 변환 실험과 루트의 생성 번들·고해상도 자산 제거.
- OCR 선별 도구와 AssetPicker는 `diagnostics/`로 이동. 기본 도구 설치에는 OCR 모델이 필요하지 않음.
- C# 서버 코드는 `mod/`, 기본 CLI는 `localize.py`로 통일.
- 새 테스트 패키지는 품목별로 생성하며 게임 확인을 마친 배포본과 구분.

삭제된 구현은 Git 이력 `4ddf197`에서 조회할 수 있습니다. 현행 코드 안에 실행 불가능한 구현을 보관하지 않습니다.
백업과 Git 이력에는 예전 자산이 남지만 새 브랜치의 현재 파일에는 게임 자산을 추가하지 않습니다.

## 기존 작업을 이어갈 때

1. 새 CLI에서 해당 품목을 `prepare`합니다. 기존 작업 폴더를 통째로 새 구조에 덮어쓰지 않습니다.
2. 검증된 원본과 편집 이미지를 비교하고, 새 원본 크기·알파·수정 영역 조건에 맞는 레이어를 가져옵니다.
3. 현재 생성 이미지는 시각 참고나 편집 입력으로 사용합니다. 원본의 비문자 영역까지 변경된 이미지가
   자동 파일 검사를 통과하도록 전체 이미지에 허용 마스크를 씌우지 않습니다.
4. 파일 검증·테스트 패키지·게임 확인을 새로 기록합니다.

최근 ChatGPT 마요네즈 D는 넓은 RGB 변화가 있는 결과입니다. 이번 재구축은 그 이미지를 재번역하거나
게임에 재설치하지 않습니다. 새 경로의 실제 자산 검사는 원본 왕복과 명시적인 작은 합성 시험 패치로 수행합니다.

## 재현 가능한 검사

기본: `python -m pytest`.

실제 자산: `python -m pytest -m game_assets --spt-root D:/SPT --dotnet <SDK10 실행파일>`.
마요네즈(한 번들)와 소시지(컬러/보조맵 분리 번들)의 원본 바이트 보존, 마스크 밖 변경 차단,
작은 시험 편집의 패키징과 게임 원본 불변을 확인합니다. 결과는 `workspace/checks/`에 남깁니다.
이 검사는 게임 렌더 검증을 대신하지 않습니다.
