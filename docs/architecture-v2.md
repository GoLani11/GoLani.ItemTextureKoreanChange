# 음식 텍스처 현지화 파이프라인 v2

## 목표

SPT의 음식·음료 포장에 남은 라틴 문자와 키릴 문자를 자연스러운 한국어로 바꾸되,
원본 UV·알파·재질·밉맵·UnityFS 구조를 보존한다. 이미지 생성은 시각 참고와 초안에
사용하고, 승인된 문구와 보존 조건은 결정적인 검증 단계로 통제한다.

게임 자산과 추출 PNG는 Git에 넣지 않는다. 저장소에는 코드, 대상 프로필, 번역 명세,
스킬과 합성·검증 규칙만 둔다.

## 구조

```text
localizer/golani_texture_localizer/  범용 Python 패키지
profiles/food/collection.json        SPT 4.0 음식 대상과 한국어 문구
skills/localize-spt-food-textures/   Codex 실행 절차
tests/localizer/                     자산 독립 단위 테스트
workspace/                           원본·시안·승인본·보고서·번들(Git 제외)
mod/                                 향후 C# 게임 적용 코드를 이관할 위치
```

기존 `tools/auto.py`, OCR 도구와 C# 프로젝트는 v2가 같은 결과를 낼 때까지 유지한다.
옛 파일을 먼저 삭제하지 않는다.

## 작업 흐름

1. `python localize.py --spt-root D:/SPT inventory`: Texture2D 메타데이터만 읽는다.
2. `python localize.py --spt-root D:/SPT extract`: 원본을 `workspace/source/`에 추출한다.
3. OCR·육안 판독: 바꿀 외국어 문구와 정확한 한국어 문구를 확정한다.
4. 이미지 편집: 품목마다 별도 초안을 만들고 원본과 비교한다.
5. `stage`: 원본 크기와 알파를 확인한 승인본만 보관한다.
6. 보조맵 생성: 원본 normal/gloss의 극성과 강도를 유지하며 글자 위치만 이식한다.
7. 재패킹: 원본 포맷과 밉 수를 유지한 동일 크기 stream payload만 교체한다.
8. 검증: 번들 레이아웃, 비대상 객체, 왕복 이미지와 변경 범위를 확인한다.
9. 설치: 별도 사용자 승인 후 백업과 해시 검증을 거쳐 적용한다.

## 완료 조건

- 현지화 대상 39개가 승인되고 외국어가 없는 3개가 보존 판정을 받는다.
- 모든 승인본의 크기와 알파 채널이 원본과 같다.
- 원본과 승인본의 적응형 경계선 F1이 0.5 이상이며 UV 구조 보존 검사를 통과한다.
- 읽을 수 있는 라틴·키릴 문구가 남지 않는다. 숫자와 법적 기호는 명세에 따라 보존한다.
- UV 섬, 이음선, 로고 도형, 주름, 오염과 비문자 영역이 이동하지 않는다.
- 원본 텍스처 포맷·밉 수·stream path/offset/size가 같다.
- 압축 왕복 후 모든 채널의 평균 절대 오차(MAE)가 6.0 이하다.
- UnityFS 디렉터리와 payload 밖 바이트가 원본과 같다.
- 재패킹 번들을 다시 열어 모든 대상 텍스처를 추출할 수 있다.
- SPT 클라이언트가 사용하는 로컬 경로에서 재패킹 번들의 전체 자산을 로드할 수 있다.
- 원본 복원에 필요한 해시와 백업 기록이 있다.

## 현재 범위

SPT 4.0 데이터베이스의 Food/Drink 직접 하위 42개 레코드를 조사했다. 보드카 중복
레코드를 합치면 실제 제품은 41종이며, 공유·잔존 텍스처를 포함한 컬러 작업 대상은
42장이다. 이 중 39장은 현지화하고 외국어 인쇄가 없는 3장은 보존한다. 내용물이나
숟가락처럼 별도 인쇄가 없는 추가 diffuse 8장은 작업 대상에서 제외한다.
